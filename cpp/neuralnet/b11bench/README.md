# Clean CUDA inference benchmark

No search, NN cache, visits, or batch-formation simulation. All heads (including
ownership) are evaluated. The default timed region repeats device forward on
preuploaded input; it includes CPU launch overhead and stream contention, but
excludes input packing/transfers, output copies, allocations and artifact setup.
Twenty warmup forwards precede timing. Concurrent streams have start and finish
barriers; they are within ONE measured engine run, not competing benchmark jobs.

Build the engine normally with Linux/Ninja, then build this optional diagnostic:

```sh
python3 cpp/neuralnet/b11bench/build.py /absolute/path/to/build
/absolute/path/to/build/b11_inference_bench \
  /path/to/model.bin.gz /path/to/config.cfg 16 1 1000 2 - /path/to/corpus.bin
```

Positional arguments are model, config, capacity, exact(0/1), iterations,
concurrent streams, raw-output prefix (`-` disables dumps), and corpus path.
Optional trailing arguments: NN board length (default19), actual batch
(default capacity), and force FP32 (default0). A missing corpus is generated
once from deterministic legal positions, using official input-v7 features.
Put corpora and outputs in an ignored/external directory. Reuse the SAME bytes
for every engine; do not compare independently generated random inputs.

The last stdout line is JSON with batch/capacity/streams, wall seconds,
`nnEvalPerSec`, and per-stream CUDA-event milliseconds. Throughput is total
completed evaluations divided by the longest stream wall interval. Record the
model/corpus/binary hashes, GPU/driver/toolkit, config and concurrency alongside
results. Compare repeated interleaved runs with other GPU/CPU compilation idle;
unlocked power/temperature/clocks can move short-run numbers by several percent.

For mask-enabled full19 throughput, pass `exact=0` with the SAME full19 corpus
generated by an exact run. For genuine padding, generate a different corpus via
`exact=0` into a NEW path: it cycles 19/13/9 boards padded to NN19. These are
different workloads and must be reported separately. Mask-channel zero marks
padding; accuracy softmax/top1 and ownership metrics must exclude those cells.

Optional diagnostics (unset all `DIRECT_*` variables for ordinary pure timing):

- `DIRECT_E2E=1`: time full getOutput, including transfers/postprocessing.
- `DIRECT_REPLAY=256`: one-stream post-timing corpus replay and raw batch dumps;
  the row count must be divisible by actual batch and a prefix is required.
- `DIRECT_GRAPH=1`: graph-capture experiment, not the production inference path.

Raw files contain FP32 pass, spatial policy (NHWC), value, score and ownership,
in that order, with counts from the model descriptor and ACTUAL batch. They are
not a model/export format. No fixed capacity-sized output reinterpretation is
used. The benchmark currently requires input-v7 (22 spatial/19 global/no meta).

The harness intentionally includes the backend implementation to access private
device buffers without expanding the engine's public API. The build helper
links all other normal engine objects and preserves Version helpers by renaming
main. It is a branch-local diagnostic, not an installed engine subcommand. The
optional `--doom` adapter enables identical timing against the reference fork.

The standalone CPU dispatch regression can reuse an existing Linux build's CPU
objects, without linking or initializing CUDA:

```sh
python3 cpp/neuralnet/b11bench/profile_test.py /absolute/path/to/build \
  --model /absolute/path/to/b11c768.bin.gz --run
```

For same-batch raw numerical comparisons, `compare_outputs.py` reports every
head plus policy/value probabilities. Supply `--corpus` and `--row-offset` for
the corresponding input rows so padded cells are excluded:

```sh
python3 cpp/neuralnet/b11bench/compare_outputs.py official.raw optimized.raw \
  --batch 13 --corpus /absolute/path/to/corpus.bin --row-offset 0
```

These probability/ownership checks are not a held-out training-loss measurement.
