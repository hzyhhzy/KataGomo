# Official Go b11c768 / RTX 5090 specialization

This is an optional FP16 specialization of the original CUDA backend, not a
separate model format and not the smaller Gomoku b11. The test model is the
official [tf3-b11c768 checkpoint](https://media.katagotraining.org/uploaded/networks/models/kata1/kata1-tf3-b11c768-s11500M-d6163M.bin.gz),
SHA256 `73f6454eba62d2f6d099af8ce66d8c3fde6225e223c55817da0627590e98b0ae`.
Selection uses structure rather than checkpoint filename or hash.

## Selection and fallback

The full bundle activates automatically only when all of these hold:

- All optional FA4 exact/mask artifacts and CUTLASS GEMMs are built in.
- Device name is NVIDIA GeForce RTX 5090, compute capability 12.0.
- Model matches `isOfficialB11C768()` in `cudab11profile.h`: model version17,
  11 nested outer blocks, trunk768/inner384, H12/D32 learned-RoPE attention,
  alternating SwiGLU FFN384→1152→384 and the checked projection/norm shapes.
- Network tensor layout is FP16 NHWC, 19×19, capacity13 or16.
- The original tensor-core attention availability probe succeeds.
- Each particular forward uses an actual batch equal to that capacity.

Any other profile uses the original generic path. In particular, a partial
actual batch is not silently padded or passed to a specialized kernel.
`cudaUseB11RTX5090=false` disables the entire bundle for comparison/debugging.
The original generic architecture list is preserved; an explicitly SM120-only
build is useful for experiments but does not support generic fallback on other GPUs.

Mask-enabled input is fully supported. On each `getOutput`, after input symmetry
packing, a CPU scan proves whether every input mask value is exactly one. Only
then may a full19 batch use the exact kernel and omit mask operations. A mixed
19/13/9 batch keeps key masking and the original masked-query/output semantics.
The full-mask flag is reset for every input batch; no state carries into the next
input. Exact inference still uses the original caller's exact-board contract.

## Retained kernels

FA4 uses M128/N96/stage1 with FP16 QK/PV accumulation and softmax rescaling.
RMSNorm384 uses warp FP32 reductions. The QKV projection now applies learned
FP32 RoPE inside its output-store iterator, after the unchanged FP16 GEMM
epilogue rounding; it removes a Q/K global-memory read/write pass and launch.
The token-major Q384|K384|V384 layout is unchanged, and V is not rotated. The
separate, batch-shared FP32 RoPE kernel remains available as an ablation/fallback.
Affine+SiLU vectorization
preserves the original FP16 affine/mask rounding before FP32 SiLU. Pointwise
projections use CUTLASS tensor-core GEMMs with FP16 accumulation/epilogues.
All weights remain the original FP16 CUDA weights; no INT8 or PTQ is involved.

### Cache policy and diagnostic controls

For eligible B13/B16 with exactly three planned inference threads on this GPU,
an eager-only persisting-L2 policy follows the long-lived outer768 and inner384
residual buffers. The setup obtains the full worker-to-device mapping from
NNEvaluator, including changes made before respawning workers. It does not infer
concurrency from a deduplicated GPU list, a config default, or another GPU's count.
Custom direct callers should call CUDA-only `setExpectedConcurrentGpuThreads()`
before creating any handles; unknown topology disables the cache optimization.

The reservation is device-global. Handles in one context share a lease, and the
last owner restores the previous quota, which can already be nonzero in a fresh
CUDA context. A different engine context causes the new L2 request to be skipped,
not a load failure. CUDA supplies no ownership identity for an arbitrary external
quota; applications managing this resource themselves should disable this policy.
An externally changed quota during our lease is not overwritten at release.
This is not an automatically rebalanced cache policy for arbitrary simultaneous
models/processes. Each forward clears its stream window before the output heads;
short actual batches and graph capture set no window. The global quota remains
reserved for the handle lifetime, so cache effects on concurrent generic work
are still possible even when that particular forward uses generic arithmetic.

`cudaB11QkvRope=false` disables just the store-stage fusion. It also respects
`cudaB11FastRope=false` and QKV bit16 of `cudaB11GemmMask`.
`cudaB11L2Mode=0` disables the cache policy (`-1`, the default, selects automatic;
1/2/3 explicitly select outer/inner/both, still requiring a known worker map).
`cudaB11L2HitRatio` defaults to1. These controls do not bypass the complete
model/device/layout/batch gate. No research environment variables are used.

The generator, dependency pins, licenses and standalone build recipe are in
[`b11aot/README.md`](b11aot/README.md). Generation needs a build-only Python
environment; the resulting engine needs no Python/PyTorch/FA4 runtime. Current
AOT artifacts are Linux x86-64 ELF; other host platforms should omit the AOT
option and keep the generic backend until native generation is validated.
The AOT loader initializes only the consuming current device during handle
setup, never during a hot launch. It supports handle/model replacement but
inherits the engine's one-shot global lifecycle: `globalCleanup()` is for program
termination, not CUDA reset followed by reinitialization in the same process.

## Measurement

[`b11bench/README.md`](b11bench/README.md) describes an independent all-head
inference benchmark, shared by official, reference and experimental engines.
It reports nnEval/s, not search visits. Batch and concurrent inference streams
are jointly screened; compare each engine's own best configuration, then run
longer interleaved repetitions with other GPU work and CPU compilation idle.
Full19 exact, full19 mask-enabled, and truly padded boards are separate workloads.

The default bundle was selected from measured candidates; removed alternatives
included CuTe FFN, RoPE tables, postConv+norm fusion and other attention tiles.
Numerical validation compares every head, policy/value probabilities, and only
valid board cells for masked-policy and ownership metrics. This is inference
parity testing, not a held-out training-loss claim.

## First-round historical result (2026-09-07)

This section records the earlier `2f948f5` bundle, before store-stage QKV RoPE
and the L2 policy. The new production result is recorded separately below.

Official reference: `231e1c4b938f068628a5e3e59a3e842ad5fc92cd`.
Doom reference: `5dfd8cb16bc0393518bdadcd1fe55ee1252da1a8`, unchanged source,
with its N96/both16 FA4 and original runtime-M GEMM registries expanded to cover
the screened batches. Its optional CuTe FFN was slower and was not selected.
Driver595.58.03, CUDA13.0.48, cuDNN9.14; power/clocks left unchanged.

After batch/stream screening, 16 explicit profiles were confirmed in three
interleaved rounds, 1000 iterations each. These are **pure-forward nnEval/s
medians**, with preuploaded inputs and all heads, not search visits or full
getOutput timings. Each reference uses its best median among the tested final
profiles; no claim of an exhaustive global optimum is made.

| Workload | Official | Doom | This bundle | vs official |
|---|---:|---:|---:|---:|
| Full19 exact | 3379.92 | 3989.37 | 4074.55 | +20.55% |
| Full19, mask-enabled API | 3354.90 | 2472.17* | 4060.44 | +21.03% |
| Real mixed19/13/9 padding in NN19 | 3636.14 | 2603.08* | 4131.79 | +13.63% |

`*` Doom has no optimized masked FA4 path in this reference; these two numbers
are its **generic masked** path, not a like-for-like masked specialization.
The exact result is **2.14% faster than Doom**, meeting the non-regression target
but not the aspirational additional10%. The exact three-run speed ranges were
3376.97–3552.69 official, 3975.26–4109.73 Doom, 4064.09–4188.36 this bundle.
Natural temperature/clock drift affects absolute rates; every interleaved exact
round favored this bundle. No power/clock locking or simultaneous benchmark jobs.

The winning bundle configuration is **batch13, three inference streams**, with
`cudaShareModelWeights=true`. The other final reference winners also used B13/S3,
except Doom generic fullmask B16/S2. Batch16 remains a validated alternative.

Output-fidelity acceptance uses 256 legal positions per corpus (B13 replays four
initial rows again to make whole batches). All P0 top choices match official
FP16; maximum group probability RMSE is P0=0.00011354, P1=0.00013189,
value=0.00038434. P1 swaps one near-tied choice on the same partial-board row at
both batches. Candidate exact/fullmask outputs are byte-identical. All eight
persistent-state comparisons and twelve final generic/no-AOT fallback pairs
pass, as do 2806 CPU profile checks. GTP loads and moves successfully, and the
official `testgpuerror -quick` passes 19-board and rectangle datasets versus FP32.
The final B13/S3 check also compares all three streams' output heads in all three
modes, with correct per-stream corpus offsets; full19 exact/fullmask outputs
remain byte-identical. AOT Python unit tests and the injected-runtime loader test
pass. Embedded ELF inspection confirms all twelve preserved generic CUDA targets.
These checks do not establish training loss, playing strength, or behavior on a
second physical GPU.

## Second-round result (2026-09-07)

The store-stage QKV RoPE and topology-aware L2 policy were retained after a new
39-case confirmation: 13 explicit profiles, three interleaved rounds of 1500
iterations, with the second round reversed before rotation. Same GPU, model and
all-head pure-forward boundary as above; each engine keeps its own previously
screened B/S candidates. B13/S3 still wins; B16/S3 is a slightly slower validated
alternative. No INT8 or model-format change, and no power/clock changes.

| Workload | Official | Doom exact | Previous bundle | New bundle |
|---|---:|---:|---:|---:|
| Full19 exact | 3387.18 | 3962.26 | 4063.75 | **4192.81** |
| Full19 mask-enabled API | 3343.17 | — | 4061.18 | **4181.18** |
| Real mixed19/13/9 padding | 3633.51 | — | 4121.90 | **4244.09** |

All entries are medians in nnEval/s. Exact is **5.82% faster than Doom**, **3.18%
faster than the previous bundle**, and **23.78% faster than official**. This still
does **not** reach the aspirational Doom+10% target. The two masked workloads
improve over the previous bundle by2.95%/2.96%; no generic Doom masked result is
substituted for a specialized masked comparison.

The first attempted second-round confirmation was deliberately aborted when its
activation check found L2 disabled: a nonzero initial quota was incorrectly
treated as proof of external ownership. A fresh CUDA process on this machine
starts at18MiB. This is not a portable constant or an ownership API. That guard
was removed, arbitrary initial values are saved/restored, and the entire formal
run was repeated under a new evidence tag (`round2-confirmation-v2`). Aborted
measurements are not included in the medians.

The rebuilt full-architecture engine passed the256-position corpora replay,
three-stream full-head comparisons, persistent-handle small-batch/mask transitions,
master-disabled and incompatible-profile checks, GTP, and official19/rectangle
`testgpuerror -quick`. CPU dispatch tests now cover4784 checks. Two low-level L2
lifecycle tests add301 checks each, including three simultaneous leases/real
streams, quota restoration and exception/capture cleanup. They are resource tests,
not three NN workers. A separate real GTP process creates three NN workers and
activates all three L2 leases. The CUDA13 no-AOT diagnostic is byte-identical to
official in all three modes/streams; it does not claim an older-toolkit GPU test.

Additional Graph,21 projection tiles,cuBLASLt,FFN epilogues,RoPE tables and
two-stage projection pipelines did not justify further production paths. The
two-stage CUTLASS variant is MmaPipelined, not a smaller cp.async multistage loop;
its QKV/out/down boundary results were respectively7.18%/0.56%/5.81% slower.
